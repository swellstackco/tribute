# Tribute — Build plan for Sonnet (one builder agent, sequential)

Read `docs/SPEC.md` first. Rules: TypeScript strict, Node 22+, American English, participant-facing text at a 4th–6th grade level, no emoji, no gradients, stationery look (SPEC §11). Commit after every task as `T<n>: <done criterion>`; stage exact files, never `git add -A`. Mock mode (`QLOO_MODE=mock`, `LLM_PROVIDER=mock`) must always work with zero keys. Never paste a key anywhere but the server `.env`. Never commit captured Qloo responses; fixtures are hand-shaped synthetic JSON. Never call the Anthropic provider in tests.

Clock: start Oct 22 evening Manila. Code freeze **Oct 28 18:00 Manila**; submit Oct 29. Estimated 30 h of agent time.

## Task list

### T1 — Scaffold (1 h)
Single package (no workspaces): `src/server/` (Express), `src/web/` (Vite, vanilla TS), `src/shared/` (types), `fixtures/`, `scripts/`, `docs/`. Scripts: `dev` (concurrently server :5117 + Vite :5173 with proxy to `/api`), `build` (Vite build to `dist/web`, tsc server to `dist/server`), `start`, `test` (vitest), `typecheck`, `probe`, `seed:examples`, `cache:clear`, `readability`, `deploy`. `LICENSE` (MIT), `.gitignore` (`node_modules`, `dist`, `data/*.db*`, `.env`, `*.log`), `.env.example` with every variable from SPEC §12 and comments, README skeleton (pitch, one-command run, not-grief-counseling line, license).
**Done:** `npm install && npm run dev` serves `/health` → `{ ok: true, qloo: "mock", llm: "mock" }` and a placeholder page on :5173; `npm test` runs one passing test; `npm run typecheck` passes.

### T2 — Qloo client: real, mock, cache, param allowlist (2.5 h)
`src/server/qloo/types.ts`: response types from SPEC §4 (`SearchResult`, `InsightsEntity` with `query.affinity` and optional `query.explainability`, `TagInsight`, `DemographicsInsight`, `TagLookup`). `client.ts`: `QlooClient` interface (`search`, `tags`, `insights`, `entities`). `real.ts`: `fetch` to `QLOO_BASE_URL` (default `https://hackathon.api.qloo.com`) with `X-Api-Key`, 8 s timeout, 2 bounded retries on 429/5xx with jittered backoff, param-name allowlist (`src/server/qloo/params.ts`, from the docs list in SPEC §4; unknown names throw in dev, are dropped with a warning in prod). `cache.ts`: SQLite `qloo_cache` keyed by `sha256(path + sorted query)`; cache-through on 200 only. `mock.ts`: loads `fixtures/qloo/*.json`; lookup by normalized signature (`search:merle haggard`, `insights:urn:entity:artist:<sorted ids>`), then by type-level wildcard (`insights:urn:entity:artist:*`), so any input returns plausible results. Fixtures: write synthetic data for the three profiles (SPEC §7) and generic per-type fallbacks: search results (flat array, `name/entity_id/types/popularity/properties/tags`), insights entities per type with realistic `properties` (artist: `tags`; book: `publication_year`, author; movie/tv: `release_year`, `image.url`; place: `address`, `geocode{latitude,longitude,city}`, `business_rating`, `price_level`, `phone`, `website`), `urn:tag` tags (`tag_id/name/subtype/types/query.affinity`), demographics (age and gender deltas), `/v2/tags` lookups (cuisine, hobby, venue tags). UUIDs are random v4; names are real public cultural entities (artists, films, authors) and fictional businesses ("Rosa's Taqueria", "Hillcrest Community Hall") for places.
**Done:** vitest: real client builds the exact query string the docs show for each of the 10 request kinds in SPEC §4 (snapshot), rejects an unknown param, caches a 200 and replays it without fetch; mock client returns a non-empty, type-correct response for every profile love and for an unknown love.

### T3 — Tool layer mirroring the harness (2 h)
`src/server/tools/`: one file per tool from SPEC §5 (`qloo_describe`, `qloo_find_tags`, `qloo_recommend`, `qloo_rank`, `qloo_entity_tags`, `qloo_audience_demographics`, `qloo_capabilities`, `ask_family`, `write_section`, `finish`). Input schemas as zod with the harness field names (SPEC §5 table). Common envelope `{ status, summary, results, result_count, error? }`; statuses `ok | empty | needs_input | partial | degraded | error`; `error = { code, retryable, recovery }` with codes `QLOO_AUTH`, `QLOO_RATE_LIMIT`, `QLOO_TIMEOUT`, `QLOO_UPSTREAM`, `TOOL_INPUT`, `PICK_NOT_FROM_QLOO`, `QUESTION_LIMIT`. `qloo_describe` ambiguity rule (two candidates within 0.15 popularity and different types → `needs_input` with candidates). `qloo_recommend` maps `target_type/signals/signal_tags/filter_location/include_tags/exclude_tags/explain/limit` to `filter.type/signal.interests.entities/signal.interests.tags/filter.location.query/filter.tags/filter.exclude.tags/feature.explainability/take`, plus `price_level_max`, `rating_min` extras (documented as Tribute extensions). `qloo_rank` uses `filter.results.entities`. Tool definitions export JSON schema for the LLM (`toolDefinitions()`), and a one-paragraph description each written for a model.
**Done:** vitest ≥ 20 tests: each tool happy path against the mock client; `needs_input` on an ambiguous fixture ("Ghost": band vs movie); `empty` on a no-result fixture; `error.retryable=true` on a simulated 429; `write_section` rejects an id not seen in the run; `ask_family` second call → `QUESTION_LIMIT`.

### T4 — LLM providers, spend ledger, caches, rate limit (2.5 h)
`src/server/llm/provider.ts` interface (`complete({ system, messages, tools, maxTokens }) → { text?, toolCalls[], usage }`). `mock.ts`: deterministic planner that, given the run state, emits the next tool call in the SPEC §5 phase order with fixed warm sentences (one per section per profile, plus generic sentences keyed by section). `anthropic.ts`: `@anthropic-ai/sdk`, model `claude-haiku-5-5`, no `thinking` field, `output_config: { effort: "low" }`, `tool_choice: { type: "auto" }`, `max_tokens: 2048`, 20 s timeout, tool inputs parsed with `JSON.parse`, typed error chain (`RateLimitError` → `APIStatusError` → `APIConnectionError`) → provider error → orchestrator falls back to mock for the rest of the run. `spend.ts`: ledger table, price table (`claude-haiku-5-5`: 0.10 / 0.50 per MTok), `canSpend()` checks `LLM_SPEND_CAP_USD` before each call. `llmCache.ts` keyed by `sha256(provider+model+messages+tools)`. `rateLimit.ts`: per-IP (`HMAC(RATE_SALT, ip)`) 6/hour, 30/day; global 400/day; example slugs exempt. Gemini adapter: **not in this task** (cut line).
**Done:** vitest: mock planner produces the full phase sequence for Walt in ≤ 16 tool calls; spend cap trips at $4.00 and `canSpend()` returns false; rate limiter returns 429 on the 7th call in an hour; LLM cache hit skips the provider (spy). Anthropic provider has a unit test with a mocked SDK client only.

### T5 — Orchestrator and event stream (3 h)
`src/server/agent/orchestrator.ts`: run loop with the limits from SPEC §5 (16 tool calls, 6 LLM turns, 45 s, one question), phase-aware system prompt (`src/server/agent/prompts.ts`; includes the tone rules, the "pick only ids from tool results" rule, the 4th–6th grade rule, and the constraints), required-steps checklist with deterministic gap filling (reuses the mock planner), `waiting` state for `ask_family` with `POST /api/tribute/:id/answer`, trace recording (`steps[]` with `source: model|planner`), run cache by input hash. Routes: `POST /api/tribute` (validate: 5–10 loves, each 2–60 chars, first name ≤ 30, city ≤ 60, constraints enum), `GET /api/tribute/:id` (plan + trace, no raw Qloo bodies), `GET /api/tribute/:id/events` (SSE: `step`, `question`, `section`, `done`, `error`; heartbeat every 10 s), `POST /api/tribute/:id/answer`. CLI `scripts/run.ts "<loves...>" --city --faith --budget --guests` prints the ledger and plan JSON.
**Done:** `npm run cli -- walt` (profile shortcut) completes in mock mode in < 2 s with a ledger of 10–16 steps and six sections, every pick id present in the trace's tool results (assert in a test); an ambiguous love pauses the run, `answer` resumes it; a second identical request replays from cache with `cached: true`.

### T6 — Plan builder: sections, evidence, links (2.5 h)
`src/server/plan/`: `sections.ts` turns tool results into the six sections (SPEC §3) with pick objects (id, name, type, affinity, properties subset, links, why). Music: resolved artists first, then recommended, dedupe, cap 8. Readings: books/authors cap 6, show `publication_year`. Food: cuisine tag names + places cap 5 with address, rating, price level as `$`–`$$$$`. Venue: places cap 5. Screen: eras = decades derived from `release_year`/`publication_year` of recommended media and the resolved artists' active decades when fixtures carry them (top 3 decades by count), plus movies/shows cap 6 with `image.url` when present. Program: fixed order of service template with the chosen music and readings slotted in; faith-based adds "opening prayer" and "closing blessing" slots (template, labeled as not a recommendation); secular uses "opening words" and "closing words." `links.ts`: `https://music.apple.com/us/search?term=<enc>`, `https://open.spotify.com/search/<enc>`, `https://www.google.com/maps/search/?api=1&query=<enc name + address>`. `evidence.ts`: per pick, the signal ids that produced it (the run's resolved loves), affinity, explainability contributions when present, and the top tags; per section a one-line "how we chose." `readability.ts`: Flesch-Kincaid grade for a string.
**Done:** vitest: Walt's mock plan has 6 sections, music ≥ 5 picks with both links, food places show price as `$$`, venue excludes bar/nightclub tags when guests = older, eras are three decades, every pick has ≥ 1 evidence row; readability of all planner sentences ≤ grade 6.

### T7 — Self-critique and revise pass (1.5 h)
`src/server/agent/critique.ts`: rules evaluated after the first plan, both deterministic and (when live) as an LLM turn: faith-based → venue must not carry bar/nightclub/brewery tags, food caterer rating ≥ 3.5; budget modest → `price_level ≤ 2` for food and venue; many older guests → venue tags must not include hiking/trail/rooftop (configurable list in `src/server/agent/constraintTags.ts`), and the program gets a "seated throughout" note; secular → no prayer slots. A failed rule re-runs `qloo_recommend` with `exclude_tags`, `price_level_max`, `rating_min` and rewrites the section; the ledger shows the step with `source: critique` and a one-line reason.
**Done:** vitest: Rosalind's mock run shows ≥ 1 critique step and a revised venue section; Dana's shows zero critique steps; a plan with an over-budget caterer gets revised and the final food list has only `price_level ≤ 2`.

### T8 — Demo profiles and precompute (1 h)
`src/shared/examples.ts`: the three profiles from SPEC §7 (loves, city, constraints, first name). `scripts/seed-examples.ts` runs each through the orchestrator in the current mode and stores `examples(slug, run_id)`; `GET /api/examples` returns slugs, names, cities, loves; `GET /api/tribute/example/:slug` returns the stored run; `POST /api/tribute/example/:slug/rebuild` re-runs live (rate-limited like a normal run).
**Done:** `npm run seed:examples` prints three run ids; `GET /api/tribute/example/walt` returns a complete plan in < 100 ms; the trace contains no key, no raw IP, no person name sent to any Qloo tool input (test greps tool inputs for the first names).

### T9 — Front end: landing, intake, ledger (3 h)
Vite vanilla TS in `src/web/`: `index.html` (landing + three example cards + "Start your own"), `intake.ts` (10 chips, mic via `webkitSpeechRecognition` when available with text always present, first name, city, three constraint selects, validation messages in plain words), `ledger.ts` (SSE consumer; rows with tool name in small caps, status pill, summary, ms; `needs_input` renders the question with two or three buttons; `aria-live="polite"`), router by hash (`#/`, `#/new`, `#/t/<id>`, `#/why/<id>`). Copy lives in `src/web/copy.ts` and is checked by the readability script.
**Done:** from a clean browser: landing → "Try an example: Walt" → plan page in < 1 s; "Start your own" → type 5 loves → ledger streams in mock mode and lands on the plan; the ambiguous demo love ("Ghost") shows the question and resumes after a click; works at 375 px wide with no horizontal scroll.

### T10 — Program page, why page, print CSS (2.5 h)
`program.ts` renders the six sections with pick cards, the order of service, and buttons (Print program, Copy playlist links, Share link, Start over). **Each pick card shows its evidence inline and always visible** (SPEC §3): name, one-line detail, links, a "Because: <loves>" line, a fit bar with the affinity number, up to three tag chips, and a "You didn't mention this" mark on picks that were not typed by the family; within a section, resolved loves come first, then unmentioned picks ordered by affinity. A "See why we chose these" link sits at the top of the page. `why.ts` renders the evidence sheet: loves → resolved entities, the tag profile ("era and vibe"), the audience shape with the sentence "This describes the audience of what they loved, not the person," then per section the picks with signals, affinity and tags, and the honest line about Qloo choosing and a language model writing. `print.css`: `@page letter` and A4, folded-program layout (two panels per sheet, cover + inside), `break-inside: avoid`, hide nav/ledger/buttons; the why page prints as its own document. "Copy playlist links" writes a plain-text list to the clipboard.
**Done:** every pick card on the Walt page shows a Because line, a fit bar with a number, and tags without any click; at least one card per section carries the "You didn't mention this" mark; Chrome "Save as PDF" of the Walt program produces a 2-sheet booklet with cover, order of service, music with links as text, readings, food, gathering place; the why page prints on its own; no element is cut mid-card; Playwright headless (muted) screenshot of both pages saved to `docs/assets/`.

### T11 — Design pass, readability gate, accessibility (2 h)
Apply SPEC §11 tokens end to end: fonts (self-hosted or Google Fonts with `display=swap`), paper/ink palette, hairline rules with the diamond ornament, small-caps labels, 17 px minimum body, 7:1 contrast check, 44 px targets, focus rings, reduced-motion, empty and error states in kind words ("We could not find a match for that one. Try another way to say it."). `npm run readability` fails CI if any string in `src/web/copy.ts` or planner sentences scores > grade 6. Remove any emoji, gradient, or "AI" wording that slipped in.
**Done:** `npm run readability` passes; Lighthouse (desktop) accessibility ≥ 95 on landing and plan pages; screenshots at 375 px and 1280 px for all five screens in `docs/assets/`; Fable reviews the screenshots before T12.
